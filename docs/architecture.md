# 系统架构

基于 GraphRAG 的投资组合配置助手,采用前后端分离架构。后端围绕 RAG 检索增强生成、
上下文缓存、意图识别、生成四个模块构建。

## 整体数据流

```
                          ┌──────────────────────────────┐
   领域知识文档(data/raw) │        离线准备阶段          │
        │                 │                              │
        ▼                 │  语义切块                    │
   语义切块 ───────────────┼─► Milvus  chunk 向量索引     │
        │                 ├─► Elasticsearch  BM25 索引   │
        │                 ├─► Neo4j   知识图谱           │
        └─────────────────┼─► Milvus  entity 向量索引    │
                          └──────────────────────────────┘

   用户 query ─► 意图识别 ─► 上下文缓存 ─► GraphRAG 检索 ─► 生成 ─► 规则校验 ─► 回答
```

## 离线准备阶段

入口:`scripts/build_offline.py`(编排见 `app/rag/offline.py`)。

| 步骤 | 模块 | 产物 |
| --- | --- | --- |
| 1. 语义切块 | `app/rag/chunking.py` | 以配置项 / 规则 / 方案为单位的 chunk |
| 2. 向量索引 | `app/rag/vector_store.py` | Milvus chunk 集合(语义召回层) |
| 3. 关键词索引 | `app/rag/keyword_store.py` | Elasticsearch BM25 索引(精确兜底层) |
| 4. 知识图谱 | `app/graph/` | Neo4j 实体与关系(结构化推理层) |
| 5. 实体向量索引 | `app/rag/offline.py` | Milvus entity 集合(实体链接层) |

知识图谱构建包含:LLM 实体抽取、LLM 关系抽取、实体消歧(以稳定编码为 ID)、
Cypher 写入。Schema 见 `docs/domain_model.md`。

## 在线执行阶段

入口:`POST /chat`,编排见 `app/pipeline.py`。

### 1. 意图识别(`app/intent/`)

轻量规则分类 + LLM 少样本兜底,将问题分为效果解释 / 方案生成 / 方案优化三类,
并过滤无效问题(超范围问题直接引导重问,不进入检索与推理链路)。

### 2. 上下文缓存(`app/cache/`)

基于 Redis 的会话状态管理。维护每轮的问题、回答、命中实体与配置项;对后续提问
判定相关轮次并拼接精简历史上下文;已扩展过的实体参与检索去重剪枝。

### 3. GraphRAG 检索(`app/rag/retrieval.py`)

- **阶段一 — 实体识别与图谱扩展**:在实体向量索引中召回 top-k 实体,在 Neo4j 中
  按依赖 / 互斥 / 影响关系做 1~2 跳扩展,得到结构化实体子图。
- **阶段二 — 子图驱动的混合检索**:以子图实体描述为查询,做向量召回 + BM25 召回,
  加权融合排序,按相似度阈值过滤,产出参考上下文与关系三元组。

### 4. 生成(`app/generation/`)

按意图选择提示词模版,组装上下文(知识文本段 + 实体关系三元组 + 历史摘要),
调用大模型生成。对含配置方案的回答,用规则系统做依赖 / 互斥 / 维度合法性兜底校验,
发现冲突时给出修正建议。

## 技术选型说明

| 关注点 | 选型 | 原因 |
| --- | --- | --- |
| 语义召回 | Milvus | 解决用户表达与文档表述不一致 |
| 精确召回 | Elasticsearch BM25 | 稳定命中配置项名称、参数阈值 |
| 结构化推理 | Neo4j | 配置项依赖 / 互斥关系天然是图结构 |
| 对话状态 | Redis | 会话级缓存,支持 TTL 与快速读写 |
| 大模型 | OpenAI 兼容接口 | 可对接任意兼容服务,部署灵活 |
